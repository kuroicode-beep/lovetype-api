# 타로 인증·결제 검증 운영 설정

2026-10-21. 기존 MBTI 웹 API와 관리자 API는 유지하고 타로 사용자 API에 인증·영수증 검증을 적용했다. 운영 서비스는 출시 전 비용 방지를 위해 중지된 기록과 상태를 확인했으므로 이번에는 재기동하지 않는다.

## 설정

- `GOOGLE_CLIENT_ID`: Google 웹 OAuth 클라이언트 ID. 앱 빌드의 `GOOGLE_WEB_CLIENT_ID`와 같아야 한다. ID 토큰의 서명·대상·만료·이메일 확인을 검사하며 개발용 JWT 본문 파싱 우회는 제거했다.
- `PLAY_PACKAGE_NAME`: `com.svil.lovetype_tarot`.
- `PLAY_SERVICE_ACCOUNT_JSON`: 해당 Play 앱의 구매 조회·소비·승인 권한이 있는 서비스 계정 JSON. Firebase 알림 계정과 같은 권한이라고 추정하지 않는다. 값을 소스·로그에 넣지 않는다.
- 기존 `DATABASE_URL`, `DEEPSEEK_API_KEY`, `FIREBASE_SERVICE_ACCOUNT_JSON` 등은 보존한다.
- iOS 결제는 서버 검증이 아직 연결되지 않아 `store_not_configured`로 거절한다. 승인·충전을 우회하지 않는다.

## 계약 변경

- 타로·결제·푸시 등록은 `Authorization: Bearer <Google ID token>`과 `app_id`를 요구한다. 요청의 `user_id`가 인증된 주체와 다르면 403이다. 미인증 로컬 닉네임의 지갑을 임의로 Google 계정에 합치지 않는다.
- `/auth/google`은 `app_id`, `id_token`을 받고 검증된 `user_id`를 반환한다.
- `/tarot/cooltime`은 문서의 `topic=daily|romance`를 지원하고 구형 `theme`도 읽는다. 미지정·잘못된 주제는 400이다.
- `/tarot`은 사용자별 DB 트랜잭션 잠금 안에서 쿨타임·잔액 확인, AI 생성, 저장, 차감, 쿨타임 설정을 수행한다. `request_id` UUID의 재전송은 저장된 결과를 반환한다. 별도 `/payment/use`는 410으로 막아 이중 차감을 방지한다.
- `/payment/charge`는 서버 상품표와 Google Play 검증 결과만 인정한다. 영수증 해시의 고유 제약과 거래로 중복 지급을 막고, 지급 commit 뒤 소비/승인을 수행한다. 스토어 완료 실패는 502로 남기며 같은 거래 재시도는 지급을 반복하지 않는다.
- 구독은 Play의 실제 만료시각을 적용한다. 운영 구독 갱신·환불 알림(RTDN) 연동은 별도 과제이며, 현재 잔액 조회는 저장된 만료시각을 넘긴 구독을 비활성으로 반환한다.
- 히스토리 저장 재시도는 `client_reading_id` 고유 키를 사용하고 잔액·쿨타임을 변경하지 않는다. 생성 응답의 `reading_id`로 다시 저장할 때는 해당 사용자 소유 리딩만 반환한다.

## 검증·배포 순서

`npm ci` → `npm test` → DB 백업 → `npm run db:tarot` → 새 앱과 서버의 인증 설정 확인 → 사용자 승인된 서비스 재개 및 실제 API·기기 테스트 순서다. 추가 마이그레이션 `sql/tarot_security.sql`은 기존 테이블·지갑을 지우지 않는다.

회귀 검사는 임시 HTTP 서버와 pg-mem을 쓴다. 실제 PostgreSQL의 advisory lock·동시 트랜잭션 및 Play API 권한·실결제를 검증한 것은 아니다. 실제 PostgreSQL 동시성 검증은 서비스 재개 전 별도로 수행한다.

원복은 직전 배포 코드로 가능하지만 추가 테이블·열은 보존한다. 기존 영수증 검증 없는 충전 경로를 공개적으로 재개하지 않는다. 배포 전에 백업과 적용·원복 기록을 추가한다.
